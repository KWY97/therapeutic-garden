# 코드 스타일

이 문서는 앞으로 수정하는 코드의 기준이다. 기존 파일을 일괄 변환하는 지침은 아니다.

## Java

- 스페이스 4칸으로 들여쓴다. 클래스·메서드 이름은 PascalCase·camelCase를 각각 사용하고, 변수는 camelCase, 상수는 UPPER_SNAKE_CASE를 사용한다.
- 여는 중괄호는 선언 또는 제어문의 같은 줄에 둔다. 메서드와 필드는 책임과 호출 흐름을 이해하기 쉬운 순서로 배치한다.
- import는 프로젝트 패키지, 외부 패키지, `java` 패키지 순으로 묶고 각 그룹 안에서 정렬한다. static import는 별도 그룹에 둔다. 불필요한 와일드카드와 미사용 import는 피한다.
- 단순 포맷팅 중 메서드 분리, 서비스 호출 순서, 트랜잭션 또는 예외 처리 동작을 바꾸지 않는다.

## JavaScript

- 스페이스 4칸, camelCase 이름, 작은따옴표와 세미콜론을 사용한다. 한 줄에 여러 문장을 작성하지 않는다.
- 자동 세미콜론 삽입, 템플릿 리터럴, 이벤트 처리 순서와 비동기 흐름을 고려해 동작을 보존한다.

## HTML·Thymeleaf

- 스페이스 4칸으로 중첩 구조를 들여쓴다. 긴 태그의 속성은 읽기 어려울 때 여러 줄로 나눈다.
- Thymeleaf 표현식, 텍스트 노드의 공백, 폼 필드와 접근성 속성의 의미를 보존한다.

## CSS

- 스페이스 4칸을 사용하고 선택자와 선언을 읽기 쉽게 줄바꿈한다.
- 선택자 우선순위, 규칙의 적용 순서, 선언 순서를 유지한다. 파일 전체 자동 포맷팅은 피한다.

## Gradle·YAML

- Gradle은 스페이스 4칸, YAML·YML은 스페이스 2칸으로 들여쓴다.
- 설정 키·값과 프로필의 의미를 변경하지 않는다. 기존 Gradle 파일의 탭 혼용은 해당 파일을 별도로 검토할 때만 정리한다.

## 적용 절차

- 포맷팅과 기능 수정은 분리하고, 작은 파일 또는 패키지 단위로 변경한다. 변경 후 관련 테스트와 전체 테스트를 실행해 동작을 확인한다.
- Git diff에서 예상치 못한 파일 변경·삭제를 확인한다. HTML 화면, JavaScript 이벤트, CSS 표시와 설정 파일은 해당 동작도 확인한다.
- `.local`, 백업, 정적 이미지·폰트 등 바이너리, `META-INF`, `ProductionDdlGuard` 안전 장치는 포맷팅 대상에서 제외한다. 운영 리소스와 DB 관련 파일은 보호하고, 필요하면 별도 작업에서 검토한다.
